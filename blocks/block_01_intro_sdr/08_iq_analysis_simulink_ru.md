# 08. Анализ записанного сигнала в Simulink

## Цель раздела
Научиться использовать Simulink для чтения записанного IQ-сигнала и наглядного анализа его временных и спектральных характеристик.

## 1. Зачем анализировать запись в Simulink
В этом блоке Simulink нужен не только как среда моделирования, но и как инструмент построения инженерной цепочки:

**записанный реальный сигнал → блочная модель анализа → подтверждение поведения сигнала**

Это важно, потому что в следующих блоках курс будет опираться на Simulink как на мост между:

- теорией;
- моделью;
- fixed-point;
- аппаратной реализацией.

## 2. Что должен сделать студент
В этой работе студент должен:

- загрузить IQ-файл в модель Simulink;
- представить его как комплексный сигнал;
- показать временную форму;
- показать спектр;
- сравнить результат с MATLAB и HDSDR;
- подготовить модель для повторного использования в следующих работах.

## 3. Общая логика модели
Простейшая модель анализа должна включать:

1. Источник данных из файла.
2. Формирование каналов I и Q.
3. Объединение в комплексный сигнал.
4. Анализ во временной области.
5. Спектральный анализ.
6. Отображение результатов.

## 4. Рекомендуемая структура модели
Примерная структура блоков:

- **Binary File Reader** (сырые файлы с чередованием I/Q) или **From Multimedia File** (WAV-записи) — оба из DSP System Toolbox
- **Data Type Conversion**
- **Demux / Selector**
- **Real-Imag to Complex**
- **Time Scope**
- **Spectrum Analyzer**

Если формат файла не поддерживается напрямую, можно:

- сначала загрузить его в рабочее пространство MATLAB;
- затем подать сигнал в Simulink соответствующим блоком.

## 5. Что нужно настроить
Перед запуском анализа задайте:

- частоту дискретизации;
- тип данных;
- длину анализируемого фрагмента;
- формат I/Q;
- шкалу отображения спектра.

## 6. Минимальная задача первого блока
Студент должен построить модель, которая позволяет:

- взять IQ-запись;
- сформировать комплексный поток;
- показать временную форму;
- показать спектральный пик тестового тона.

Этого уже достаточно, чтобы Simulink стал частью практического маршрута курса.

## 7. Что должно наблюдаться
### Во временной области
- регулярная структура сигнала;
- стабильная амплитуда;
- отсутствие грубых искажений.

### В спектре
- выраженный пик;
- стабильное положение по частоте;
- уровень шума;
- возможные боковые составляющие.

## 8. Сравнение с другими инструментами
После анализа в Simulink полезно сравнить результат с:

- наблюдением в HDSDR;
- спектром в MATLAB;
- анализом в Python.

Студент должен убедиться, что один и тот же сигнал:

- узнаётся в разных средах;
- даёт согласованные результаты;
- подтверждает правильность эксперимента.

## 9. Практическая ценность этапа
Этот этап особенно важен, потому что дальше Simulink будет использоваться не только для анализа, но и для:

- синтеза сигналов;
- подготовки к fixed-point;
- структурного описания тракта;
- перехода к аппаратной реализации.

Поэтому уже в первом блоке Simulink должен стать для студента «рабочим инструментом», а не только теоретической средой.

## 10. Что включить в отчёт
Рекомендуется включить:

- изображение модели Simulink;
- окно анализа во временной области;
- окно спектрального анализа;
- краткое описание параметров модели;
- сравнение с MATLAB или HDSDR.

## 11. Выводы
После этого раздела студент должен:

- уметь использовать Simulink для анализа записанного IQ-сигнала;
- понимать, как реальная запись встраивается в блочную модель;
- видеть связь между офлайн-анализом и будущей аппаратной реализацией.
