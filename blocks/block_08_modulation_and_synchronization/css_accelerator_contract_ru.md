# Контракт учебного CSS-ускорителя

[English version](css_accelerator_contract.md)

Issue [#46](https://github.com/Lay007/zynq-sdr-course/issues/46) реализуется
последовательно. Текущий этап курса — читаемый базовый тракт SF7:

```text
поток IQ Q1.15
  -> регистровый dechirp с насыщением
  -> буфер символа на 128 отсчётов
  -> явный интерфейс адреса/данных чтения
  -> 128-точечное DFT-ядро с одним комплексным MAC
  -> поток valid/index/комплексное значение/магнитуда для бинов
  -> детектор первого и второго максимумов
```

`css_dft128_core.v` отвечает только за преобразование. После заполнения буфера
символа ядро запускается, управляет адресом чтения и последовательно выдаёт бины
от 0 до 127. Управляющую границу образуют сигналы `start`, `busy` и однократный
`done`; при новом запросе запуска во время вычисления импульсом поднимается
`start_rejected`. Reset прерывает незавершённое преобразование и возвращает ядро
в состояние idle. Ядро не зависит от внутренней памяти и логики поиска максимумов
старого монолитного детектора.

`css_peak_detector.v` отвечает за поиск первого и второго максимумов. Он получает
только индекс бина и поток магнитуд, при равенстве сохраняет первое вхождение и
выдаёт удерживаемые регистры результата с однократным импульсом `done`. Его
управление и поведение при reset проверяются отдельной регрессией.

## Интерфейс и арифметика

- Отсчёт передаётся при `valid_in && ready`.
- Один символ состоит ровно из 128 принятых отсчётов; загрузка следующего символа
  не перекрывается с вычислением DFT.
- IQ и коэффициенты опорного сигнала — знаковые Q1.15.
- Dechirp после комплексного умножения Q2.30 выполняет усечение, насыщает результат
  до Q1.15 и увеличивает `dechirp_overflow_count` для каждого насыщенного отсчёта.
- Отсчёты DFT и twiddle-коэффициенты — знаковые 16-битные Q1.15. Каждое из четырёх
  вещественных умножений даёт знаковый 32-битный результат Q2.30. Комплексные
  сложение и вычитание явно расширены до 33 бит перед арифметическим сдвигом
  вправо на 15.
- Сдвинутые комплексные слагаемые накапливаются в знаковых 32-битных регистрах;
  вещественная и мнимая части выходного бина имеют ту же разрядность.
- Каждый аккумулятор возводится в квадрат с 64-битным знаковым результатом. Два
  произведения складываются на ширине 64 бита и образуют `magnitude_squared`.
- Внутри DFT-ядра насыщения нет. Для входов Q1.15 и 128 отсчётов сумма помещается
  в знаковый 32-битный аккумулятор, а магнитуда — в положительный диапазон
  знакового 64-битного значения. Для входов вне этого контракта переполнение не
  контролируется.
- При равных магнитудах сохраняется первое вхождение благодаря строгому сравнению
  `>`.
- `done` — однократный импульс результата; выходные регистры затем удерживают
  последнее значение.

Последовательному DFT требуется `128 * (128 + 1) = 16 512` тактов MAC/выдачи на
символ плюс такты загрузки, завершения конвейера и управления. Реализация подходит
для изучения fixed-point поведения и задания bit-exact эталона, но не заменяет
потоковый FFT для SF5–SF12.

## Воспроизведение

```bash
python blocks/block_08_modulation_and_synchronization/python/generate_css_sf7_detector_vectors.py
python tools/run_block8_css_rtl.py
```

Самостоятельная DFT-регрессия проверяет reset/abort/restart, отклонение повторного
запуска, все 128 событий и индексов бинов, однократные импульсы valid, отсутствие
X/Z и каждое комплексное значение и магнитуду по общему Python fixed-point
эталону. Детерминированный dechirped tone для символа 37 имеет максимум в бине 37.
Отдельная регрессия peak-детектора проверяет управление кадром, паузы valid,
равные максимумы, reset/abort/restart и отсутствие X/Z в результате. Сквозная
регрессия детектора охватывает все 128 неискажённых SF7-символов, а также
детерминированные случаи CFO и шума. Перед симуляцией CI заново создаёт входные
векторы детектора и twiddle-таблицы из сохранённого Python-эталона.

## Текущие ограничения и следующая граница

Это последовательный учебный DFT, а не оптимизированный по пропускной способности
FFT. RTL-симуляция подтверждает проверенное fixed-point и управляющее поведение,
но не доказывает timing closure Zynq-7020, использование ресурсов или работу на
плате. Симуляционную задержку нельзя переводить в допустимую аппаратную частоту
без отчётов Vivado.

Следующий шаг вычислительного тракта — заменить `css_dft128_core` на переиспользуемый
FFT, сохранив контракт чтения буфера, поток бинов и независимый peak-детектор.
Для завершения issue #46 всё ещё нужны измеренные задержка и пропускная способность,
утилизация LUT/FF/BRAM/DSP, отчёты timing и максимальной частоты отсчётов,
AXI-Stream для данных, AXI-Lite для управления/статуса и PS-side помощник запуска.
