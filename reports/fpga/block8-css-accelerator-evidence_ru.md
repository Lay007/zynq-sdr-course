# CSS-ускоритель блока 8: результаты реализации Vivado OOC

[English version](block8-css-accelerator-evidence.md)

## Результат

Vivado 2021.1 полностью маршрутизирует `css_sf7_sequential_detector` в режиме
out-of-context и выполняет ограничение `100 МГц` для `xc7z020clg400-2`:

| Метрика | Результат |
|---|---:|
| WNS | `+0.526 нс` |
| TNS | `0.000 нс` |
| Нарушенные endpoints | `0 / 2142` |
| Задержка критического data path | `9.412 нс` |
| Полностью разведённые сети | `1562 / 1562` |
| Сети с ошибками маршрутизации | `0` |
| DRC-нарушения уровня Error | `0` |
| Post-route оценка по критическому периоду | `105.552 МГц` |

Частота вычислена из routed-ограничения и setup slack. Она показывает запас,
но не является характеристикой максимальной надёжной тактовой частоты.

## Воспроизведение

Команда выполняется из корня репозитория в Windows. Vivado должен быть задан в
`VIVADO_BIN` или установлен в стандартном каталоге Xilinx:

```powershell
python tools/generate_block8_css_vivado_reports.py
```

Проверить и повторно опубликовать уже существующие отчёты без нового запуска
Vivado можно так:

```powershell
python tools/generate_block8_css_vivado_reports.py --reuse
```

Flow создаёт проект только в памяти, читает сохранённые RTL и ROM-таблицы,
ограничивает `clk` периодом `10.000 нс` и выполняет `synth_design -mode
out_of_context`, `opt_design`, `place_design`, `phys_opt_design` и
`route_design`. Публикуются нормализованные post-synthesis и post-route отчёты.
Vivado project, build-каталог, checkpoint, bitstream, log и journal не создаются
в отслеживаемом дереве.

## Использование ресурсов

| Ресурс | Использовано | Доступно в XC7Z020 | Доля |
|---|---:|---:|---:|
| Slice LUT | 631 | 53 200 | 1.19% |
| Slice registers | 421 | 106 400 | 0.40% |
| BRAM tiles | 1.5 | 140 | 1.07% |
| DSP48E1 | 16 | 220 | 7.27% |

После синтеза используются 693 LUT при тех же количествах регистров, BRAM и
DSP. Физическая оптимизация при размещении объединяет 62 LUT, поэтому routed
результат использует 631 LUT. По иерархическому отчёту dechirp использует 4 DSP,
DFT-ядро — 12 DSP, а symbol buffer и peak detector не используют DSP. Буфер
символа реализован на distributed RAM; Vivado также выводит три примитива
RAMB18E1 для таблиц поиска.

## Задержка и пропускная способность

Количество тактов подтверждено WSL/Icarus-регрессиями. Скорости рассчитаны для
ограниченной частоты `100 МГц`, а не для неподтверждённой оценки Fmax.

| Метрика | Такты | Результат при 100 МГц |
|---|---:|---:|
| Последовательное 128-точечное DFT | 16 640 | 166.400 мкс |
| Последний принятый отсчёт → `done` | 16 644 | 166.440 мкс |
| Первый принятый отсчёт → `done` | 16 771 | 167.710 мкс |
| Интервал запуска символов | 16 772 | 5 962.318 символов/с |
| Установившаяся скорость принятых отсчётов | — | 763 176.723 отсчёта/с |

Установившаяся скорость предполагает 128 последовательных принятых отсчётов и
обязательный интервал обработки. Во время работы последовательного DFT новые
отсчёты непрерывно принимать нельзя. Для учебной конфигурации SF7 с
`BW = 125 кГц` и одним отсчётом на chip требуется `125 000 отсчётов/с` и
`976.5625 символа/с`, что ниже архитектурной скорости при 100 МГц.

## Timing-изменения

Потребовались две границы конвейера, не меняющие численный результат:

- DFT регистрирует каждое масштабированное комплексное слагаемое перед
  рекуррентным аккумулятором;
- dechirp front end регистрирует коэффициент reference ROM вместе с
  соответствующим IQ-отсчётом перед комплексным умножителем.

Все 128 комплексных DFT-бинов остаются bit-exact относительно Python-эталона.
Сквозная регрессия по-прежнему проходит 128 неискажённых символов и
детерминированные случаи CFO/шума.

## Интерпретация routing и DRC

`report_route_status` помечает дизайн как `Fully Routed`: все 1562
маршрутизируемые сети разведены, ошибок маршрутизации нет. Финальный DRC-отчёт
содержит ноль нарушений уровня Error и 46 предупреждений методики:

- 44 предупреждения рекомендуют более глубокий входной/выходной конвейер DSP48;
- одно предупреждение `RTSTAT-10` относится к внутренним сетям результата и
  статуса без маршрутизируемой нагрузки в изолированном top-level;
- одно предупреждение `ZPS7-1` напоминает, что полный Zynq-дизайн должен
  содержать PS7.

Рекомендации по DSP не мешают текущему закрытию timing на 100 МГц, но указывают
на возможную оптимизацию мощности и более высокой частоты. Два остальных
предупреждения ожидаемы на OOC-границе и должны быть перепроверены после
системной интеграции.

## Ограничения результатов

- Это implemented OOC timing изолированного детектора, а не timing closure
  полного PS/PL-проекта платы.
- AXI-логика, PS7, формирование clock/reset, floorplanning и полный дизайн могут
  изменить использование ресурсов и slack.
- Ограничены только внутренние пути `clk`. Для 34 входных и 161 выходного порта
  намеренно не заданы I/O delays; у OOC-портов также нет `HD.PARTPIN_LOCS`.
- Bitstream не создавался, работа на аппаратуре не проверялась.
- Следующий уровень доказательств — интегрированная AXI/PS-обвязка, полный
  placed-and-routed timing и аппаратный smoke test.

Машиночитаемые и нормализованные исходные отчёты находятся в
`reports/fpga/block8_css_vivado_ooc_raw/`.
