# Проект 12.4 — Полный измерительный отчёт по SDR

## Цель

Подготовить полный, основанный на измерениях отчёт по SDR, объединяющий моделирование, реализацию, настройку RF, запись IQ, синхронизацию и метрики.

## Зачем это нужно

Остальные три проекта тренируют каждый по одному навыку. Этот проверяет, можете ли вы удержать вместе всю цепочку и честно её отчётно описать: схема системы, совпадающая с тем, что вы реально построили; RF-настройка, которую другой человек мог бы воспроизвести; набор данных с происхождением; метрики с заявленными определениями; и вывод, вытекающий из чисел, а не из надежды. Это результат, который реально прочитает коллега или работодатель.

## Требуемая структура отчёта

| Раздел | Содержание |
|---|---|
| Требования | цель и критерии успеха |
| Архитектура | схема системы и форматы данных |
| Реализация | модель, fixed-point, RTL или скрипты |
| Настройка RF | частоты, усиления, ослабление |
| Набор данных | файл IQ, метаданные и запись в реестре |
| Результаты | графики и метрики |
| Обсуждение | ограничения и источники ошибок |
| Воспроизводимость | команды и окружение |

## Что должен содержать каждый раздел

| Раздел | Минимум, который ожидает рецензент |
|---|---|
| Требования | опровержимое предложение и числовые цели, зафиксированные **до** измерения |
| Архитектура | одна схема; числовой формат на каждом интерфейсе; какие части — железо, какие — ПО |
| Реализация | какой код дал числа (путь в репозитории и коммит); согласие модели и реализации выражено числами |
| Настройка RF | центральные частоты, частота дискретизации, усиления TX и RX, ослабление, кабельный или антенный тракт и процедура безопасного выключения; для стенда с передатчиком — доказательство RF-безопасности (кабельный ослабленный тракт или экранированная установка) |
| Набор данных | происхождение, формат, контрольная сумма, место хранения и почему исходный файл находится или не находится в Git |
| Результаты | у каждого графика есть оси, единицы и указание прогона, из которого он получен; каждое отношение сопровождается сырыми счётчиками, по которым оно рассчитано |
| Обсуждение | минимум одно ограничение и одна отвергнутая гипотеза; источники ошибок ранжированы по тому, насколько они могут сдвинуть результат |
| Воспроизводимость | одна команда, заново создающая или проверяющая метрики без исходного стенда |

## Минимальные результаты

- итоговый отчёт;
- запись в реестре наборов данных;
- JSON с метаданными;
- набор графиков;
- таблица метрик;
- команды воспроизводимости;
- ограничения и следующие шаги.

## Таблица «прошёл/не прошёл»

| Критерий | Цель | Измерено | Статус |
|---|---:|---:|---|
| Частотная ошибка |  |  |  |
| SNR |  |  |  |
| EVM |  |  |  |
| BER |  |  |  |
| Доля ограничения |  |  |  |

Заполняйте столбец *Цель* из замороженных требований до измерения. Статус — **PASS**, **FAIL** или **NOT MEASURED**; критерий, который не удалось измерить, указывается как таковой, а не пропускается и не заполняется правдоподобным числом. Прогон, не достигший цели, — допустимый результат, если измерение корректно, а причина локализована.

## Дисциплина доказательств

Курс различает три вида доказательств, и отчёт обязан указать, какого вида каждое число:

| Вид | Смысл | Как пометить |
|---|---|---|
| синтетические | получены моделью или сгенерированным набором данных | напишите «синтетика» рядом с графиком и в манифесте |
| воспроизведённые | анализ сохранённого захвата | укажите манифест и контрольную сумму |
| измеренные | получены вживую на железе в этом проекте | укажите установку, настройки и число повторных прогонов |

Никогда не выдавайте синтетический или воспроизведённый результат за аппаратное измерение. Повторные прогоны важны: один удачный BER 0 на нескольких тысячах бит говорит мало; укажите, сколько бит сравнено и по скольким независимым прогонам (сравните с [Лабораторной 8.7](lab-8-7-snr-vs-ber-traps.md)).

## Ворота верификации

1. **G0 — план:** требования, цели и каркас таблицы pass/fail закоммичены.
2. **G1 — модель:** эталонная модель достигает целей в симуляции.
3. **G2 — реализация:** реализация согласуется с моделью в пределах заявленного допуска.
4. **G3 — установка:** настройка RF задокументирована и безопасна; контрольный захват (известный тон) подтверждает частотную ось и порядок каналов.
5. **G4 — измерение:** набор данных записан с метаданными и контрольной суммой; проверки качества (DC, ограничение) проходят либо их отказ объяснён.
6. **G5 — анализ:** метрики вычислены с заявленными определениями и внесены в таблицу.
7. **G6 — воспроизведение:** чистый checkout проверяет метрики по сохранённым артефактам.
