# Лабораторная 11.8 — Overlay gpreg BPSK для AD9361 и первый разведочный пакет

## Краткое изложение на русском

**Цель.** Перейти от заглушки запуска через AXI-Lite к первому специфичному для курса аппаратному overlay AD9361, который сохраняет видимую для PS плоскость управления, пока восстанавливается точно подходящий к плате загрузочный shell:

```text
PS / ПО -> axi_gpreg @ 0x79040000 -> ступенчатый мост домена отсчётов -> тракт TX/RX AD9361
```

Это первая чистая передача от исполняемого модема Блока 5 к импортированному вендорскому shell AD9361, соответствующему реальной плате курса (`xc7z020clg400-2`).

**Инженерное решение (по состоянию на `2026-06-21`).** Закоммиченный режим overlay намеренно сведён к `gpreg_only`. Откат сделан сознательно: он держит путь управления простым и проверяемым, сохраняет видимую для Linux оболочку RX и TX DMA, чтобы стоковое дерево устройств по-прежнему нормально опознавалось, отделяет проверку карты адресов `axi_gpreg` от более трудной проблемы чистой загрузки AD9361 и не позволяет считать пересобранный, но ещё не безопасный для загрузки образ PL допустимой RF-базовой линией. Прежние эксперименты с TX с включённым пакетом остаются историческим доказательством, но не текущей безопасной закоммиченной базой.

**Контракт регистров.** Базовый адрес `0x79040000`. Идентификатор ядра `axi_gpreg` (смещение `0x004`) — `0x4250534B`. Управление: `0x404` (бит `0` — фронт старта, бит `1` — сброс залипающего done, биты `3:2` — режим решения RX), `0x444` `FRAME_BIT_COUNT`, `0x484` `PREAMBLE_COUNT`, `0x4C4` `START_OFFSET`. Статус: `0x408` (бит `1` — busy, бит `2` — залипающий done, бит `3` — залипающий таймаут RX), `0x448` `RECEIVED_BITS`, `0x488` `TOTAL_ERRORS`, `0x4C8` `PAYLOAD_ERRORS`, `0x508` подпись моста, `0x548` упакованные `TX_VALID_COUNT` и отладка знака решений RX, `0x588` `RX_VALID_COUNT`, `0x5C8` упакованное слово `CAPTURE_DEBUG` сырого отвода RX. Полные описания упаковки битов — в английском тексте ниже.

**Следующий порядок повторного включения (по этапам).**

1. Убедиться, что кандидат пользовательского загрузочного образа PL принимается соответствующим валидатором: сырой `.bit` через `validate_clean_boot_overlay.py` либо `.bit.bin` через `validate_manual_uart_fpga_load.py`.
2. Подтвердить IP платы, регистр ID `axi_gpreg` и подпись моста до записи параметров кадра.
3. Снова включить мост домена отсчётов, сохраняя видимую для Linux оболочку DMA неизменной.
4. Держать ослабление TX AD9361 на минимальной доступной мощности.
5. Держать усиление RX низким и ручным. Не включать AGC для первого возобновлённого пакета.
6. Запустить только один короткий пакет.
7. Наблюдать `busy`, затем `done` либо `done после таймаута`.
8. Прочитать `RECEIVED_BITS`, `TOTAL_ERRORS` и `PAYLOAD_ERRORS`.
9. Только после этого возобновлять повторные развёртки или кампании BER.
