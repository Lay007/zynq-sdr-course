# Лабораторная 11.10 — Снимок RX по IIO по таймеру вокруг разведочного пакета

## Цель

Выяснить, показывает ли приёмный поток AD9361 какое-либо событие с энергией вокруг разведочного BPSK-пакета, запущенного через gpreg, ещё до того, как цепочка BER сообщит ненулевые `RECEIVED_BITS`.

## Инженерный вопрос

> Если плоскость управления gpreg завершает работу, но `RECEIVED_BITS` остаются нулевыми, показывает ли поток IIO на стороне хоста всё-таки событие RF/IF по времени вокруг запуска пакета?

## Скрипт

| Файл | Назначение |
|---|---|
| `blocks/block_11_integrated_sdr_project/python/lab_11_10_iio_burst_capture.py` | запускает короткий захват `iio_readdev`, запускает один пакет gpreg по SSH/devmem и записывает JSON-отчёт с метриками мощности захвата |

## Почему этот шаг важен

Разведочная RF-развёртка уже показала, что плоскость управления жива, но не ответила на более узкий вопрос:

- видна ли на потоке RX DMA AD9361 хоть какая-то энергия, похожая на пакет;
- происходит ли это событие около намеченного времени запуска;
- остаётся ли проблема в основном в RF-видимости или уже внутри тракта согласованного фильтра / BER.

Это различие меняет следующий шаг отладки.

## Пример запуска

```bash
python blocks/block_11_integrated_sdr_project/python/lab_11_10_iio_burst_capture.py \
  --ssh-host 192.168.40.1 \
  --ssh-user root \
  --ssh-password analog \
  --iio-uri ip:192.168.40.1 \
  --sample-count 2097152 \
  --trigger-delay-ms 10 \
  --json-out docs/assets/lab110_iio_burst_capture_live.json
```

## Контракт отчёта

JSON-отчёт должен содержать:

- состояние AD9361 до захвата по таймеру;
- состояние AD9361 после необязательной RF-настройки и после восстановления;
- число байт `iio_readdev` и необязательный путь выходного файла CI16;
- результат пакета gpreg и снимок регистров;
- оконные метрики мощности относительно ожидаемого времени запуска.

## Интерпретация

Особенно полезны три исхода:

1. `energy_event_detected = true`, и событие близко ко времени запуска.
2. `energy_event_detected = true`, но далеко от времени запуска.
3. `energy_event_detected = false`, а захват выглядит как один стационарный шум.

Первый случай указывает на выравнивание цифровой приёмной цепи. Третий возвращает к RF-видимости, включению TX или связи тракта.
