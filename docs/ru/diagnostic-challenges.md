# Диагностика неисправной SDR-цепочки

[English version](../en/diagnostic-challenges.md)

Четыре дополнительных упражнения учат переходить от правдоподобного результата
к проверяемому диагнозу. Вы получаете реализацию с намеренной ошибкой, записываете
гипотезу, измеряете симптом, вносите небольшое исправление и проверяете регрессию.
Все результаты относятся к синтетическим моделям или RTL-симуляции. Плата,
передатчик и записи реального RF-сигнала не используются.

| Случай | Что изучить сначала | Наблюдаемый симптом | Проверка |
| --- | --- | --- | --- |
| `cfo` | [Лабораторная 8.1](labs/lab-8-1-cfo-estimation-correction.md) | Остаточная частота после коррекции | CFO в Гц, EVM, ошибки / число сравниваемых бит |
| `iq` | [Лабораторная 2.1](labs/lab-2-1-sampling-axis-and-interpretation.md), [9.1](labs/lab-9-1-iq-file-format-and-metadata.md) | Тон оказывается по другую сторону нуля | Знак спектрального пика, комплексная ошибка, границы int16 |
| `fir` | [Лабораторная 4.1](labs/lab-4-1-fixed-point-fir.md), [5.2](labs/lab-5-2-fir-rtl-mapping.md) | Малый сигнал проходит, большой меняет знак | Точное совпадение целых отсчётов, ошибка в LSB |
| `axis` | [Лабораторная 5.4](labs/lab-5-4-axis-wrapper.md) | Паузы приводят к потере или повтору отсчётов | Очередь принятых транзакций и проверки сброса |

## Сначала сформулируйте прогноз

Нужны Python 3.12 или новее и зависимости разработчика из курса. Активируйте
окружение по инструкции в README репозитория и выполните из корня:

```bash
python -m pip install -r requirements-dev.txt
python practice/diagnostics/check.py init build/my-diagnostics
```

Команда создаёт `learner.py`, `axis_iq_passthrough.v` и `report.md` в новом рабочем
каталоге, исключённом из Git. Повторная инициализация существующего каталога
отклоняется. Перед каждым случаем скопируйте шаблон отчёта и запишите:

1. Что ожидается: знак частоты, числовой диапазон или такт передачи?
2. Какая ошибка могла бы объяснить сбой? Какое есть альтернативное объяснение?
3. Какое измерение позволит отличить эти объяснения?

Проверяйте по одному случаю:

```bash
python practice/diagnostics/check.py check --case cfo --implementation build/my-diagnostics/learner.py --output build/my-diagnostics/cfo-before.json
python practice/diagnostics/check.py check --case iq --implementation build/my-diagnostics/learner.py --output build/my-diagnostics/iq-before.json
python practice/diagnostics/check.py check --case fir --implementation build/my-diagnostics/learner.py --output build/my-diagnostics/fir-before.json
python practice/diagnostics/check.py check --case axis --rtl build/my-diagnostics/axis_iq_passthrough.v --output build/my-diagnostics/axis-before.json
```

Неизменённая стартовая реализация должна провалить каждый случай. Коды выхода:
**0** означает прохождение выбранных проверок, **1** означает обнаруженный дефект
поведения, **2** означает ошибку команды, исключение в реализации или недоступный/
неисправный инструмент. Исправьте свою копию и повторите команду с именем результата
`-after.json`. Сохраните команды до и после изменения, объясните причину исправления
в отчёте. Прохождение эталонной реализации не означает выполнения работы студентом.

Для AXI нужны `iverilog` и `vvp` в `PATH`. В Windows Python-проверки можно запускать
из PowerShell, а RTL из WSL. В WSL нужны собственные Python-зависимости и Icarus;
запускайте команды из того же checkout по пути `/mnt/...`. Windows-окружение Python
нельзя использовать как Linux-окружение.

## Контракты и последовательные подсказки

### CFO: направление коррекции

Вход содержит по одному комплексному отсчёту QPSK на символ при 1 Мотсч/с,
умноженному на `exp(+j*2*pi*f*n/fs)`. Оценку `estimated_hz` даёт алгоритм
лабораторной 8.1. Реализуйте `correct_cfo(rx, estimated_hz, sample_rate_hz)`, сохраняя
число отсчётов и амплитуду. Проверяются CFO +2750, -3170 и 0 Гц, по 2048 символов,
без шума и с независимым шумом I/Q с RMS 0.002, seed 85.

Требуется модуль остаточной CFO менее 1 Гц, EVM менее 2% и ноль ошибок на 4096
сравниваемых бит в каждом случае. EVM считается относительно известных переданных
символов без дополнительного выравнивания усиления или фазы. Это фиксированные
пределы синтетического упражнения, а не чувствительность приёмника или RF-измерения.

<details markdown="1">
<summary>Подсказка 1: прогноз</summary>

Если фаза принятого сигнала увеличивается на положительный угол с каждым отсчётом,
в какую сторону должен вращаться корректирующий множитель?

</details>

<details markdown="1">
<summary>Подсказка 2: измерение</summary>

Посмотрите на `residual_cfo_hz` до анализа созвездия. Остаток около удвоенной
внесённой CFO отличает неверный знак от отсутствия коррекции. Проверьте также
отрицательную и нулевую CFO.

</details>

### IQ: порядок компонентов и сопряжение

Реализуйте `decode_iq(interleaved)` для знаковых int16 в порядке
`[I0, Q0, I1, Q1, ...]`, с делением на 32768 для получения комплексных Q1.15.
Упражнение начинается с уже прочитанных целых значений; порядок байтов файла
рассматривается в лабораторной 9.1. Здесь 1024 отсчёта при 8192 отсч/с, тоны
+1000 и -1504 Гц, амплитуда 0.65 и начальная фаза 0.31 рад. Квантование в целые
значения входит в модель сигнала.

Пик должен сохранить исходную частоту со знаком, а EVM быть менее 0.01%.
Отдельные граничные векторы требуют комплексную ошибку менее `1e-12`, обнаруживая
ошибки знаковости, масштаба и порядка, которые можно не заметить по модулю спектра.

<details markdown="1">
<summary>Подсказка 1: прогноз</summary>

Что происходит с `exp(j*w*n)` при комплексном сопряжении? Совпадает ли фаза
результата перестановки I/Q с фазой сопряжённого сигнала?

</details>

<details markdown="1">
<summary>Подсказка 2: различение</summary>

Для `z = I + j*Q` перестановка даёт `Q + j*I = j*conj(z)`.
Обе операции отражают частоту; дополнительная четверть оборота отличает их.
Сравнивайте комплексную ошибку отсчётов вместе со знаком спектрального пика.

</details>

### FIR: разрядность аккумулятора и формат Q

Реализуйте `fir_q15(samples, coefficients)` как причинный FIR с нулевым начальным
состоянием. Коэффициент с индексом ноль умножается на самый новый отсчёт.
Возвращайте по одному целому значению на входной отсчёт без хвоста фильтра.
Входы и коэффициенты имеют формат Q1.15. Сохраняйте полную сумму Q2.30,
округляйте к ближайшему, при равенстве к положительной бесконечности, затем
насыщайте до [-32768, 32767]. Это правило округления четырёхотводного FIR блока 5.
[Учебный пилот FIR/Q15](practice-fir-q15.md) использует округление к ближайшему
чётному: результаты на половине LSB отличаются. Перед сравнением явно выберите контракт.

Проверка использует рассчитанные вручную векторы: нулевой вход, несимметричный
импульсный отклик, положительные/отрицательные половины LSB, усиление малого
сигнала, обе границы насыщения и произведение `-32768 * -32768`.
Все выходы должны совпасть точно. Стрессовые коэффициенты намеренно дают усиление
выше единицы: они проверяют арифметические пределы и не являются рекомендацией фильтра.

<details markdown="1">
<summary>Подсказка 1: граница суммы</summary>

Каково наибольшее положительное произведение двух знаковых 16-битных значений?
Сколько знаковых бит нужно для суммы четырёх таких произведений? Выходное
насыщение не исправляет переполнение, уже случившееся в аккумуляторе.

</details>

<details markdown="1">
<summary>Подсказка 2: различение</summary>

Четыре граничных произведения могут дать `2**32`: нужны 34 знаковых бита.
Произведение Q1.15 имеет 30 дробных бит. Малый сигнал позволяет отличить неверный
сдвиг от ограничения; полношкальные случаи отличают переполнение аккумулятора от
переполнения при сужении выхода. Целые числа Python сохраняют полную сумму.

</details>

### AXI: считайте передачи, а не такты

Правьте модуль `axis_iq_passthrough` в рабочем каталоге. У него один тактовый
домен и синхронный сброс низким уровнем. Данные занимают 32 бита: знаковые I в
битах 15:0 и Q в битах 31:16; `tlast` отмечает каждый восьмой принятый вход.
Эталон содержит одну регистровую ступень: задержка один такт без остановок,
до одного принятого отсчёта за такт, переменная задержка при backpressure. CDC нет.

Проверка учитывает `valid && ready` по значениям перед фронтом, сравнивает
данные, порядок и `last`, требует стабильности выходных valid/data/last во время
остановки. Есть входные паузы, длительные и повторные остановки выхода,
одновременные входные/выходные передачи и сброс с ожидающим выходом.
Сброс удаляет буферизованные данные; после него новая последовательность из 64
принятых отсчётов должна выйти ровно по одному разу.

<details markdown="1">
<summary>Подсказка 1: прогноз</summary>

Можно ли принять новый отсчёт, когда выходной регистр занят и остановлен?
Должен ли valid оставаться высоким после передачи выхода, если нового входа нет?

</details>

<details markdown="1">
<summary>Подсказка 2: локализация</summary>

Изменение остановленного выхода указывает на перезапись. Выход без соответствующего
принятого входа указывает на устаревший valid или повтор. Начните с указанного
такта; учитывайте передачи только на положительных фронтах при valid и ready.
Отделяйте неблокирующее обновление регистров от значений, прочитанных на фронте.

</details>

## Проверка самого упражнения

Эталоны и намеренно ошибочные варианты находятся отдельно от файлов студента.
Эталон AXI взят из лабораторной 5.4. Преподавательская команда требует прохождения
четырёх эталонов и отклонения десяти дефектных вариантов (восьми Python и двух RTL):

```bash
python practice/diagnostics/check.py self-test --with-rtl --output build/diagnostics-controls.json
python -m pytest tests/test_diagnostic_challenges.py -q
```

Для Python используйте `self-test`, для RTL `self-test --rtl-only`.
Отсутствие симулятора, ошибка компиляции или незавершённая симуляция не считаются
обнаруженным дефектом. Отдельный CI `diagnostic-challenges.yml` требует оба набора
инструментов; общий pytest может пропустить RTL-тест при отсутствии Icarus.

JSON содержит хеш проверенного исходника, хеш проверяющего кода, seed, метрики и
уровень доказательств; для RTL также хеш testbench, версию симулятора и лог.
Храните учебные отчёты локально. Здесь нет результатов тайминга/ресурсов FPGA,
измерений RF, автоматических сертификатов или доказательства корректности для
любых входов. Конечный набор случаев показывает конкретные дефекты и не заменяет
исчерпывающую верификацию.
